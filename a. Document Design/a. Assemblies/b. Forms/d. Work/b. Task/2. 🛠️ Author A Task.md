# 🛠️ Author A Task

## 1. Prepare from governing context

Apply the shared Work Form preparation. Read applicable Work Management and
domain guidance, inspect relevant current state, and account for the authoring
harness limitations before defining Steps.

Do not turn this authoring preparation into Task Steps unless an activity
independently contributes to the Task outcome.

## 2. Use Work Management identity and storage

Use Work Management's registration/allocation mechanism for a standalone Task.
Do not manually invent the next repository-global Work ID when automation owns
it.

## 3. State outcome and acceptance

Write one independently executable outcome and observable acceptance
conditions.

## 4. Record current state and next action

Make the Task resumable without prior conversation.

## 5. Add Steps only when useful

Use checkbox-backed Steps for actions inside the same acceptance boundary. Split
or promote work when independent lifecycle or acceptance is required.

## 6. Trigger executor capability reasoning

Keep a brief instruction that the executor confirm its current harness can
perform and validate the Task safely and surface material limitations.

## 7. Validate representation

Check the required sections, checkbox-backed Steps, resumability, and absence of
duplicated Work Management semantics.
