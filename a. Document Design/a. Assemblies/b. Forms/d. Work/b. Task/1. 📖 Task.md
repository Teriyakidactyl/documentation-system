# 📖 Task

## 1. Scope

This Form governs Markdown representation for a standalone Task. Work Management
owns the Task's lifecycle, Work ID, storage, actionability, relations, and
close-out semantics.

## 2. Core sections

Use:

```markdown
## Outcome
## Acceptance conditions
## Current state
## Next action
```

Add `## Steps` only when several actions share the same Task acceptance
boundary.

## 3. Steps

Represent every Step with a Markdown task-list checkbox. A Step has no
independent lifecycle state.

## 4. Executor capability check

Before acting, the executor confirms that its current harness can perform and
validate the Task safely. Record a capability limitation only when it changes
execution, blocking, handoff, or acceptance.

This is a reasoning trigger, not a static inventory of the author's tools.

## 5. Completion condition

A Task representation conforms when its outcome and acceptance are observable,
its current state and next action are resumable, any Steps are checkbox-backed,
and material execution-environment constraints are visible where needed.
