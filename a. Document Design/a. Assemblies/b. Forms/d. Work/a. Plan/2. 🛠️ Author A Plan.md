# 🛠️ Author A Plan

## 1. Establish durable Plan storage

Create or identify storage that the executing agent can retrieve after
conversation compaction, interruption, or handoff before treating the Plan as
execution authority.

Use `.project/Planning/Plans/` and repository Work Management identity
mechanisms for repository-local Plans when they are available. When they are
not available to the current harness, use another durable artifact store and
state that limitation. Do not manually invent a repository Work ID.

## 2. Perform authoring preparation

Apply the shared Work Form preparation before finalizing executable
decomposition:

1. inventory materially relevant authoring-harness capabilities and limits;
2. read applicable Work Management guidance;
3. identify the domains and operations implied by the outcome;
4. read the governing guidance for those operations according to its directive;
5. inspect enough current state to expose presently discoverable implementation,
   validation, handoff, and completion implications; and
6. continue guidance/capability discovery when new governed concerns appear.

This is plan-authoring work. Do not turn it into the Plan's first Tasks merely
because the author had to perform it.

## 3. Resolve Planning semantics

Use Work Management Planning guidance to establish the outcome, acceptance
boundaries, Plan-local Tasks, dependencies, Gates, execution frontier, and
current state.

When preparation reveals additional work required to achieve the outcome,
record that work as discovered planned work. Distinguish the work discovered
from the activity that discovered it.

## 4. Create the Plan envelope

Add the controlled Plan metadata and H1. Bind Form provenance when supported.

## 5. Write outcome, acceptance, constraints, and decisions

Write the Plan outcome and acceptance conditions before the Task sequence.
Record constraints and decisions that affect execution or handoff.

## 6. Add the persistent execution-environment check

Keep an early Plan instruction requiring each executing agent to assess its own
current harness before entering the execution frontier.

Do not freeze the author's tools as execution truth. Prompt for materially
relevant retrieval limits, persistence, execution capability, network/external
calls, connector permissions, mutation authority, and specialized tools.

## 7. Create each Task heading

Use an H3 with the Plan-local ID and concise acceptance-boundary title:

```markdown
### T1 — Reconcile Work Management semantics
```

Keep the heading outside the state callout.

## 8. Render non-terminal Task state

Immediately beneath the heading, use the callout matching current state:

- Ready: `> [!NOTE] State: Ready`
- Active: `> [!IMPORTANT] State: Active`
- Blocked: `> [!WARNING] State: Blocked`
- Review: `> [!CAUTION] State: Review`

Put Acceptance and Steps inside the callout.

## 9. Write checkbox-backed Steps

Represent every Step with Markdown task-list syntax. Do not create a separate
lifecycle state for a Step.

## 10. Render completed Tasks

Remove the callout when a Task reaches Completed. Strike through its heading,
state, acceptance information, and explanatory text. Keep completed Step
checkboxes checked and retain useful completion evidence.

## 11. Separate every Task

Place `---` after every Task block, including the final Task before Current
state.

## 12. Maintain dependencies and Gates

Keep Task prerequisites and Gates current with the semantic Plan. When a local
Task is promoted to a standalone Task, replace duplicate lifecycle content with
a reference to the registered standalone Work ID.

## 13. Maintain resumability

Update Current state and Next action whenever the execution frontier materially
changes. Another agent must be able to continue from durable Plan state without
prior conversation.

## 14. Validate representation

Before handoff or close-out, verify durable persistence, the executor capability
check, heading/callout state treatment, checkbox-backed Steps, completed Task
rendering, Task separators, and the absence of repository-global IDs assigned to
ordinary Plan-local Tasks.
