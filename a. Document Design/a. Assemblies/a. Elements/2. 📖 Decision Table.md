# 📖 Decision Table

## Anatomy

A decision table is one heading-bounded element with one row per complete rule.
Columns hold the inputs a reader can test and the resulting action or outcome.

## Source specimen

```markdown
## Retry decision
<!--

  path:
    uid: EEG680
    filepath: 2 Technical Writing/3 Document/2 Document Elements/2 📖 Decision Table.md
  version: '1.0'
-->

| Condition | Additional condition | Result |
|---|---|---|
| Request is idempotent | Failure is transient | Retry |
| Request is idempotent | Failure is permanent | Stop |
| Request is not idempotent | Any failure | Escalate |
```

## Constraints

Make rows mutually distinguishable and collectively cover the states the
element claims to decide. Put testable conditions before the result column.
Do not hide precedence in prose; when row order matters, state that order as a
column or explicit rule.
