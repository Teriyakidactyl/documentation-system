# Document Design

Document Design governs the document-specific decomposition and representation
of documented information as an interface for completing work.

Domain-independent structural reasoning establishes conceptual units,
relationships, ownership, containment, convergence, and constraints that a
representation must preserve. Document Design applies the additional forces
that arise because a document filesystem is directly traversed by readers and
agents: representative workflows and jobs-to-be-done, progressive disclosure,
context locality, routing, folder and file placement, and Folder README and
Index interaction.

The immediate subdomains separate three responsibilities:

- **Document** owns reusable Document Forms and Document Elements.
- **Document Control** owns durable identity, addresses, controlled links,
  indexing mechanics, storage and control state, and maintenance of the chosen
  representation.
- **Technical Writing** owns how a selected document unit communicates.

These responsibilities cooperate on one document representation without
becoming authorities for domain-independent conceptual structure.
