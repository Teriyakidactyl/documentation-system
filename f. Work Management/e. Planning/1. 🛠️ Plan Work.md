# 🛠️ Plan Work

## 1. State the outcome and acceptance boundary

Write the repository outcome in observable terms. List the conditions that make
the Plan complete and the constraints that remain binding during execution.

Separate the work outcome from the current plan representation. A Plan can be
restructured without changing what successful work means.

## 2. Decide the minimum formalization level

Use the least structure that makes execution deterministic enough:

1. checklist when one actor can safely execute an obvious sequence;
2. stable node IDs when work must be referenced or handed off;
3. explicit relations when ordering, blocking, provenance, or coordination
   matters;
4. Gates when a dependency needs a checkable sufficiency threshold;
5. cycles, validation schedules, and commitment classification only when the
   problem actually contains them.

Higher formalization does not invalidate simpler Plans.

## 3. Establish Plan nodes

Create nodes for independently reasoned or independently stateful work. Typical
node roles are Task, Investigation, Decision, Validation, milestone, external
condition, and deliverable-producing work.

Do not split one cohesive Task merely to make the graph look detailed. Do not
merge nodes whose owners, lifecycles, or acceptance conditions diverge.

When a node needs independent execution state, materialize it as a Work Object
with its own Work ID. Otherwise it may remain a Plan-local node.

## 4. Establish relations

For every pair where order or coupling matters, determine whether they are
independent, prerequisite, soft dependency, or mutually coupled.

For each dependency, state what the upstream node must produce before the
downstream node can safely fire. Reject an edge whose only meaning is "A before
B" when no sufficiency condition can be stated.

Represent multiple independent edges explicitly rather than hiding them in
filesystem nesting.

## 5. Add Gates

Turn each load-bearing dependency threshold into a checkable Gate. Name the
condition, observable evidence, and minimum threshold.

For a cycle, add an exit Gate. For a terminal validation property that must be
seeded throughout upstream work, add a continuous check rather than waiting
until the end to discover the property could no longer be constructed.

## 6. Consider commitment cost

Mark a node `reversible`, `stabilizing`, or `locking` when early execution
would materially change rework cost.

Perform locking work only after its upstream Gates are sufficiently stable.
Allow stabilizing work to float to the earliest point its Gates permit.
Defer reversible work when earlier commitment provides no execution benefit.

## 7. Strengthen the plan when ordinary decomposition is weak

Consult `Reference/` when the plan is underspecified, overly linear, trapped
in one framing, causally uncertain, difficult to compare, or consequential
enough to justify adversarial review.

Use the external cognition material to generate or test the plan. Do not copy a
method into the Plan merely because it exists in the taxonomy.

## 8. Compute the execution frontier

Identify incomplete executable nodes whose prerequisites and Gates are
satisfied now.

Record blocked nodes with their unsatisfied conditions. Keep priority separate
from dependency.

## 9. Write resumable current state

Record:

- current frontier;
- active node or nodes;
- blocked work and unmet Gates;
- unresolved decisions;
- changed assumptions;
- next action; and
- the repository authority/evidence required for that next action.

Another agent should be able to continue without prior conversation.

## 10. Maintain instead of rewriting history

Update the Plan when the graph, Gates, acceptance boundary, or current state
changes.

Preserve decisions or history only when they have a future retrieval job.
Current plan prose should describe current execution truth rather than narrate
every previous arrangement.

## 11. Close the Plan

When the outcome is satisfied or coordinated work intentionally ends, apply
Close Work. Ensure every surviving current rule or artifact has its proper
owner and every incomplete residual item has an explicit disposition.
