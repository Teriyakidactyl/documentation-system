# 🛠️ Set Up Work Management

## 1. Select the repository root

Run setup against the repository root that will own the Work Management state.

Do not place `.project/` beneath a documentation subfolder when the work
belongs to the repository as a whole.

## 2. Run repository-automation setup

Use the Repo Manager Work Management setup operation.

Setup materializes:

```text
.project/
├── README.md
├── metrics.json
├── Intake/
│   ├── Ideas/
│   ├── Feedback/
│   ├── Issues/
│   └── Faults/
├── Planning/
│   ├── Plans/
│   ├── Investigations/
│   └── Decisions/
├── Execution/
│   ├── Tasks/
│   └── Handoffs/
└── Archive/
    ├── Intake/
    │   ├── Ideas/
    │   ├── Feedback/
    │   ├── Issues/
    │   └── Faults/
    ├── Planning/
    │   ├── Plans/
    │   ├── Investigations/
    │   └── Decisions/
    └── Execution/
        ├── Tasks/
        └── Handoffs/
```

Setup uses `.gitkeep` anchors only where Git would otherwise lose an
intentionally empty leaf.

## 3. Preserve existing Work Objects

When `.project/` already contains Work Objects, do not replace, renumber, or
move them merely to complete the skeleton.

Scan their `work.id` and `work.type` metadata before initializing allocator
state.

Stop on duplicate or malformed standalone Work IDs rather than guessing which
record should survive.

## 4. Initialize and reconcile metrics

Create or reconcile `.project/metrics.json` so every next-ID counter is
strictly greater than the largest allocated number of that kind found anywhere
under active or archived `.project/`.

Do not fill gaps by reusing historical numbers.

Treat `metrics.json` as operational state. Actual Work Objects remain the
recoverable semantic truth.

## 5. Establish controlled UID state

When the host repository uses controlled UIDs, let repository automation mint
missing UIDs for metadata-bearing `.project/` artifacts while preserving
existing UIDs.

The JSON metrics file and `.gitkeep` anchors are operational files, not Work
Objects and do not require Work Object UIDs.

## 6. Validate the initialized project

Confirm:

- every canonical folder exists;
- no duplicate standalone `work.id` exists across active and Archive;
- every allocator counter is ahead of all allocated IDs for its kind;
- existing Work Objects retained their identity and location unless another
  Work Management procedure required a move; and
- `.project/` remains excluded from any distribution policy that excludes
  dot-prefixed paths.

Setup is complete when a new standalone Work Object can be registered without
manual ID selection.
