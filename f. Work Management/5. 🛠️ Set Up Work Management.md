# 🛠️ Set Up Work Management

## 1. Select the repository root

Run setup against the repository root that owns Work Management state.

## 2. Run repository automation

Use:

```text
python3 "d. Software/Work.py" setup [repository_root]
```

Setup materializes:

```text
.project/
├── README.md
├── metrics.json
├── Planning/
│   ├── Plans/
│   ├── Investigations/
│   └── Decisions/
├── Execution/
│   ├── Tasks/
│   └── Handoffs/
└── Archive/
    ├── Planning/
    │   ├── Plans/
    │   ├── Investigations/
    │   └── Decisions/
    └── Execution/
        ├── Tasks/
        └── Handoffs/
```

## 3. Preserve existing Work Objects

Do not replace, renumber, or move existing Work Objects merely to complete the
skeleton.

Automation recognizes legacy Idea, Feedback, Issue, and Fault Work IDs for
validation/migration even though current setup no longer creates Intake storage
for those categories.

Stop on duplicate or malformed standalone Work IDs.

## 4. Reconcile metrics

Setup/reconcile migrates version 1 metrics to version 2 and keeps active
Investigation, Decision, Plan, Task, and Handoff counters strictly ahead of
allocated IDs.

Do not recycle historical numbers.

## 5. Establish controlled UID state

Let repository automation mint missing UIDs for metadata-bearing `.project/`
artifacts while preserving existing UIDs.

## 6. Validate the initialized project

Confirm the current skeleton exists, active allocator counters are ahead of
allocated Work IDs, legacy Work Objects remain readable when present, existing
identities are preserved, and `.project/` remains excluded from applicable
distribution policy.

Setup is complete when a new Task or Plan can be registered without manual ID
selection.
