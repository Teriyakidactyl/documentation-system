# 🛠️ Execute And Hand Off Work

## 1. Select from the execution frontier

Choose incomplete work whose prerequisites and Gates are satisfied. Use
priority only to order members already in that frontier.

Before acting, read the Work Object's current state, next action, governing
authority, and linked evidence required by the next step.

## 2. Mark active execution

Set the selected object to `active` when execution begins and update its
current-state snapshot whenever a materially different repository state would
change what a resuming agent should do.

Do not use status updates as a substitute for performing the work.

## 3. Preserve decisions at their proper owner

Record local execution choices in the Work Object only while they remain
working information. When a choice becomes durable architecture provenance,
use the ADR Form. When it becomes current authority, update the artifact that
owns the rule.

## 4. Record blocking conditions

When progress cannot continue, set `state: blocked` and identify:

- the unsatisfied condition;
- the Work Object or external event responsible when known;
- evidence showing why the condition is unsatisfied; and
- the next check or action that can change the state.

Do not encode "waiting" as a priority.

## 5. Enter review only when a gate requires it

Use `state: review` when the Task's own execution is complete but a declared
review, approval, or Validation gate still determines acceptance.

Ordinary author self-checking is not automatically a separate review state.

## 6. Write the handoff snapshot

Before interruption or transfer, make the Work Object answer:

```text
Changed:
Current state:
Next action:
Blocked by:
Governing authority:
Evidence:
```

Omit fields that are genuinely empty except Current state and Next action.

Create a separate Handoff Work Object only when the continuation package has an
independent recipient, lifecycle, or retrieval need. Otherwise keep the
handoff in the Task or Plan.

## 7. Resume from repository state

A resuming agent treats the repository as the continuity source. Re-read the
applicable repository guidance, then the active Work Object and only the linked
evidence needed for its next action.

Do not assume prior conversation, unstored intermediate reasoning, or an old
queue snapshot remains valid.

## 8. Route completion to Close-Out

When acceptance conditions are satisfied, or execution should end for another
reason, follow Close Work. Execution does not invent its own terminal semantics.
