# 📖 Fault

## 1. Fault Work Object

A Fault Work Object represents an observed failure that has a continuing work
job: diagnosis, remediation, recurrence control, or retained failure evidence.

A Fault is not identical to a Validation Fault. Validation uses that term for a
confirmed criterion violation inside a bounded assurance frame. A Work
Management Fault begins from an observed repository failure event.

## 2. Evidence

Fault evidence states what happened and how the observation can be
reconstructed. Keep observation distinct from causal interpretation.

A fault record can carry:

- observation and expected behavior;
- affected repository state or artifact;
- reproduction or smallest useful counterexample;
- causal analysis and uncertainty;
- resulting investigation or remediation links; and
- recurrence control.

Historical evidence does not become current authority merely because it
explains why current authority changed.

## 3. Cause

Use explicit causal relationships when evidence supports them. Distinguish
confirmed cause, contributing condition, and unresolved hypothesis.

Do not require every Fault to reach one root cause before useful remediation
can begin. Create an Investigation when uncertainty itself needs independently
tracked work.

## 4. Remediation

Use `remediates` from Task to Fault or an equivalent inverse projection.

One Fault can produce several Tasks: immediate repair, broader corrective
change, regression coverage, documentation correction, or recurrence
prevention. One Task can remediate several Faults only when its acceptance
boundary genuinely resolves each.

## 5. Recurrence control

A recurrence control is the durable mechanism that makes the same failure less
likely or more detectable. Examples include current guidance, a test, a schema
constraint, a validation rule, an interface invariant, or another controlled
mechanism owned by its proper domain.

The Fault links to the control. It does not own the control's current rule.

## 6. Fault close-out

Close a Fault only when its required investigation and remediation disposition
are explicit. `completed` means the Fault's own acceptance boundary is met,
not necessarily that every desirable improvement discovered during diagnosis
was performed.

Record unresolved residual risk when it materially affects later work.

## 7. Legacy `.fault` compatibility

Existing repositories may retain historical Fault Records under the reserved
`.fault/` sideband. Do not bulk-move those records merely to adopt Work
Management.

New Work Management-native fault state belongs under
`.project/Intake/Faults/`. A legacy Fault Record can remain evidence and be
linked from a new Fault Work Object when continuing work exists.
